# Бот-квиз «Крис»

Telegram-бот для проведения квизов на **aiogram 3**. В боте две роли:

- **администратор** — создаёт категории, загружает вопросы, просматривает и удаляет их,
  создаёт комнату и запускает квиз. Администратор может играть наравне с остальными:
  перейдя по ссылке-приглашению `?start=room_<код>`, он входит в комнату как участник
  и попадает в общий список игроков и таблицу лидеров;
- **игроки** — заходят по ссылке-приглашению в личном диалоге с ботом, отвечают на вопросы
  с таймером, получают таблицу лидеров.

Весь интерфейс — только inline-кнопки. Всё временное хранится в FSM, постоянные данные — в PostgreSQL.

## Запуск

1. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Создайте `.env` на основе `.env.example` и заполните данные PostgreSQL и токен бота:

   ```
   POSTGRES_NAME=my_db
   POSTGRES_HOST=localhost
   POSTGRES_PORT=5432
   POSTGRES_PASSWORD=changeme
   POSTGRES_USER=postgres

   BOT_TOKEN=123456:PUT-YOUR-TOKEN-HERE
   BOT_ADMINS=[123456789]
   ```

   Токен берётся только из `.env`, в коде он не хранится.

3. Запустите бота:

   ```bash
   python bot.py
   ```

   Таблицы создаются автоматически при старте. Активные квизы при перезапуске
   помечаются прерванными, участники получают уведомление.

Запуск через Docker:

```bash
docker compose up --build
```

## Структура проекта

```
project/

└── bot/
    ├── filters/           # user.py — IsPlayer, admin.py — IsAdmin
    ├── handlers/
    │   ├── user/          # commands.py, room.py, game.py
    │   └── admin/         # start.py, category_create.py, category_view.py,
    │                      # questions_add.py, quiz_create.py, room.py
    ├── keyboards/
    │   ├── user/          # room.py, game.py
    │   └── admin/         # start.py, category_create.py, category_view.py,
    │                      # questions_add.py, quiz_create.py, room.py
    ├── templates/
    │   ├── user/          # commands.py, room.py, game.py
    │   └── admin/         # start.py, category_create.py, category_view.py,
    │                      # questions_add.py, quiz_create.py, room.py
    ├── services/          # room.py, game.py, scoring.py, broadcast.py
    └── utils/             # states.py, constants.py, codes.py, questions_add.py
```

Принцип: **имя файла = сценарий**, и оно одинаково в `handlers`, `keyboards` и `templates`.
Папки `services` и `utils` общие и не делятся по ролям.

В хендлерах нет текстов и подписей кнопок — они берутся из `templates` и `keyboards`.
Бизнес-логика (комнаты, ход квиза, очки, рассылка) живёт в `services`.

## Сценарии администратора

1. **Создать категорию** — название текстом, проверка на пустое/длинное/дубликат,
   подтверждение (зелёная) / удаление (красная).
2. **Посмотреть категорию** — список категорий и вопросов (с пагинацией), полный просмотр
   вопроса с пометкой правильных вариантов ✅. Удаление вопроса — без подтверждения,
   удаление категории — с подтверждением (вместе со всеми вопросами). Категорию из активной
   комнаты удалить нельзя.
3. **Добавить вопросы** — выбор категории и загрузка `.json`-файла. Вопросы **дописываются**
   к существующим. Строгая валидация с указанием номера проблемного вопроса.
4. **Создать квиз** — выбор категории и таймера (3/5/10/15 сек), генерация ссылки
   `https://t.me/<bot>?start=room_<код>`, счётчик «Участников: N» со списком имён
   (first_name + last_name), кнопки
   «Начать квиз» / «Завершить квиз». Администратор автоматически становится участником
   комнаты (счётчик сразу учитывает его), поэтому он играет наравне с остальными.

## Ход квиза

- Вопросы выдаются в случайном порядке, варианты тоже перемешиваются.
- Каждому игроку приходит сообщение с вопросом, кнопками вариантов и таймером (полоска `🟩⬜`).
  Таймер каждого игрока работает отдельной `asyncio.Task` и не блокирует остальных.
- Выбор можно менять до конца времени; повторное нажатие снимает выбор.
- Когда время вышло, сообщение с вопросом у каждого игрока сразу заменяется итогом:
  правильные ответы, кто угадал, и таблица лидеров (🏆 у мест 1–3). Отдельного
  сообщения «Время вышло» нет.
- Если правильных вариантов несколько, об этом пишется и в вопросе («Правильных ответов
  несколько — отметьте все»), и в итоге.
- Через 5 секунд приходит следующий вопрос. После последнего — финальная таблица,
  комната получает статус «завершена».

### Начисление баллов

Правильных вариантов может быть несколько. Очки за вопрос начисляются так:

- если выбран **хотя бы один неверный** вариант — за вопрос **0 баллов** (даже если рядом
  был верный: 2 верных + 2 неверных = 0, 1 верный + 4 неверных = 0);
- если выбраны **только верные** варианты — **+1 балл за каждый** из них; неполный набор
  верных допускается (отмечен 1 верный из 2 — это +1 балл);
- пустой выбор — 0 баллов.

## Формат JSON-файла с вопросами

Корень файла — **массив вопросов**. У каждого вопроса есть `text` и список `options`.
Каждый вариант — объект с полями `text` (строка) и `is_correct` (булево).

```json
[
  {
    "text": "Какой тип данных в Python неизменяемый?",
    "options": [
      { "text": "list", "is_correct": false },
      { "text": "tuple", "is_correct": true },
      { "text": "dict", "is_correct": false },
      { "text": "set", "is_correct": false }
    ]
  },
  {
    "text": "Какие из перечисленных языков являются компилируемыми?",
    "options": [
      { "text": "C++", "is_correct": true },
      { "text": "Go", "is_correct": true },
      { "text": "Python", "is_correct": false },
      { "text": "Rust", "is_correct": true },
      { "text": "JavaScript", "is_correct": false }
    ]
  }
]
```

Правила проверки:

- файл с расширением `.json`, корректный JSON в кодировке UTF-8, ограничен по размеру;
- корень — непустой список;
- у вопроса непустой `text` и от 2 до 8 вариантов;
- у варианта непустой `text` (до 64 символов) и `is_correct` типа `bool`;
- в вопросе есть хотя бы один правильный вариант;
- тексты вариантов внутри вопроса не повторяются.

Готовый пример лежит в `questions_example.json`.

## Что добавлено в существующие модули

- `db/psql/models/models.py` — модели `QuizCategories`, `QuizQuestions`, `QuizRooms`,
  `QuizRoomPlayers`, `QuizRoomAnswers`.
- `db/psql/crud/admin.py` — функции работы с категориями, вопросами, комнатами и игроками.
- `bot/filters/admin.py` — `IsAdmin` расширен на `CallbackQuery`.
- `bot/filters/user.py` — добавлен фильтр `IsPlayer` (рядовой игрок, не админ). Фильтр
  применяется к сообщениям; callback-кнопки игровой части (`u_ans`, `u_leave`) доступны
  и администратору, чтобы он мог играть.
- `bot/handlers/user/commands.py` — оставлен под команды и приветствие `/start`,
  демо-логика про фьючерсы удалена.
